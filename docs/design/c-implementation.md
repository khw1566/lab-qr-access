# C안 펌웨어 적용

## 큰 출입 버튼과 움직이는 아트

- 사용자 참고 그림에 맞춰 1024×600 화면을 재배치했다. 상단 파란 영역에 제목·시계·날짜를 모으고, 검은 64px Bold 제목을 왼쪽에 배치했다.
- QR 출입 버튼은 640×148px로 키우고 지문 이미지와 64px 글자를 사용한다. 그 아래 480×88px 회색 안내 버튼과 물음표 이미지를 배치했다. 설정은 오른쪽 아래의 큰 이미지 버튼으로 표시한다.
- 손으로 그린 아이콘은 PC에서 렌더링한 Lucide·Material 이미지로 교체했다. JPG 원본과 보드용 비트맵을 함께 보관한다. 라이선스와 재생성 방법은 `firmware/assets/README.md`를 참조한다.
- 오른쪽은 정적인 3D 그림 대신 Processing 스타일의 생성형 애니메이션이다. 7개 곡선으로 구성한 입체 매듭이 회전하고 호흡하며, 점들이 곡선 위를 흐른다.
- `ui_art.c`에서 수학 곡선을 계산해 LVGL로 직접 그린다. 프레임 이미지나 동영상 파일은 사용하지 않는다. 50ms 주기로 갱신하며 대기 화면에서만 진행한다. 설정·출입 확인·스캔 화면에서는 갱신하지 않는다.
- PC 검토용 `docs/design/home-motion-preview.html`에서 같은 수식의 움직임을 볼 수 있다. 실제 LCD 캡처는 아니다.
- 검증: 고정 문구 14개의 폭 및 글꼴 포함 확인, PC 캔버스가 350ms 사이 변화하는 것을 확인했다. 컴파일·링크·COM22 업로드 모두 종료 코드 0. 앱 크기 0x3A1550, 앱 파티션 39% 여유. 업로드 데이터 해시 검증 통과.
- 재시작 후 12초 로그에서 카메라 프레임 메시지 3개와 서버 ping 성공 1개를 확인했다. 해당 구간에 패닉·워치독·화면/카메라 시작 실패는 관측하지 못했다. 실제 LCD의 애니메이션 속도와 터치·출입 결과는 별도 확인 대상이다.

## 아이콘과 Bold 글꼴 정리

- 반복 설명을 제거했다. 대기는 제목·QR 출입 버튼·시계, 인식은 휴대폰 아이콘과 한 줄 안내를 중심으로 한다.
- 홈·안내·설정·Wi-Fi·출입 결과를 같은 두께의 선 아이콘으로 표시한다. LVGL의 선·원·사각형 그리기를 사용해 글꼴 기호와 비트맵 확대에 의존하지 않는다. 탐색 동작에는 짧은 이름을 함께 표시한다.
- 이용안내의 문단은 가입·이용 신청·출입증의 세 아이콘으로 바꿨다. 오류가 발생하면 필요한 안내는 한 줄로 표시한다.
- 기존에는 Regular만 사용했다. 이제 본문 24px는 Regular, 버튼 28px·관리 제목 40px·큰 제목 56px·시계 64px는 실제 NanumGothic Bold 원본에서 생성한다. 한글과 영문·숫자를 같은 원본으로 만들어 QR과 시계의 굵기도 통일한다.
- Bold 원본: Google Fonts의 `ofl/nanumgothic/NanumGothic-Bold.ttf`. 기존 `third_party/nanum-gothic/OFL.txt`와 함께 배포한다.
- 글꼴 생성: 211개 글자 × 6개 크기, 종료 코드 0. 실제 글꼴 메타데이터 `NanumGothic / Bold`를 확인했다.
- 문구 확인: `python firmware/tools/check_ui_layout.py`, 종료 코드 0. 고정 문구 11개가 할당 폭 안에 들어가고 모든 크기에 필요한 한글·영문이 포함되어 있다. 실제 LCD 렌더링과 터치 확인은 별도다.
- 컴파일·링크·바이너리 생성 및 COM22 업로드 모두 종료 코드 0. 앱 크기 0x2FE7A0, 앱 파티션의 50% 여유. 업로드 데이터 해시 검증 통과 후 재시작했다.

2026-11-03, 선택한 C안(블루 웨이파인딩)을 실제 LVGL 화면에 반영했다.

- 흰 배경, #2447DB 상단 바와 주요 버튼, #142979 제목을 사용한다.
- 대기 화면은 왼쪽 출입 안내, 오른쪽 시각, 아래 큰 출입 버튼으로 구성한다.
- QR 인식 화면은 왼쪽 안내와 오른쪽 360×360 파란 영역을 사용한다. 영상은 기존 960×540 버퍼를 유지하고, 148/256 배율로 줄여 가운데 312×312 영역을 표시한다. 카메라 및 QR 인식 입력 해상도는 변경하지 않는다.
- 출입 결과는 승인·거부·연결 실패를 서로 다른 색상과 기호, 안내 문구로 표시한다. 통신 중에는 진행 표시를 사용한다. 결과 표시가 끝나면 대기 화면으로 돌아가고, 중복 QR 인식의 조용한 종료는 현재 화면을 유지한다.
- 이용안내는 실제 서비스 URL의 QR코드와 네 단계 안내를 표시한다.
- 관리자 PIN, Wi-Fi 목록, 비밀번호 입력 화면에 같은 색상과 버튼 형태를 적용했다. PIN 인증과 Wi-Fi 연결 로직은 유지했다.
- LVGL 9의 실제 객체 태그 `struct lv_obj_t`에 맞춰 설정 화면의 전방 선언을 수정했다.
- 나눔고딕의 24/40/48px 글꼴을 생성했다. 고정 제목은 실제 글꼴과 화면 폭에 맞춰 시안보다 일부 작게 조정했다. 기존 Montserrat 48px 시계를 사용한다.
- 상단 연결 문구는 실제 Wi-Fi 상태를 표시한다. Wi-Fi 연결을 서버 연결 성공으로 표시하지 않는다.

## 확인 결과

- SDK: ESP-IDF 5.5.5, ESP32-P4, LVGL 9.2.2. 설치된 헤더 및 기존 빌드 정보로 확인했다.
- 글꼴 생성: `firmware/tools/gen_hangul_font.py`, 종료 코드 0. 156개 글자 × 3개 크기.
- 문구 확인: `python firmware/tools/check_ui_layout.py`, 종료 코드 0. 고정 문구 18개가 할당한 폭 안에 들어가며 소스의 한글을 모든 크기의 글꼴에 포함했다. 실제 LVGL 렌더링 결과를 의미하지 않는다.
- 컴파일·링크·바이너리 생성: 설치된 SDK와 도구 경로를 설정하고 `C:\Espressif\tools\ninja\1.12.1\ninja.exe -C firmware/build` 실행, 종료 코드 0.
- 결과: `firmware/build/lab_door.elf`, `firmware/build/lab_door.bin`. 앱 크기 0x28C9A0, 0x600000 앱 파티션의 58% 여유. 빌드 과정의 파티션 크기 검사 통과.
- 일반 `export.ps1` 초기화는 로컬 `espidf.constraints.v5.5.txt` 누락으로 실패했다. 기존에 구성된 빌드와 설치된 Python·컴파일러·CMake·Ninja·ccache 경로를 사용해 최종 빌드를 완료했다. SDK 버전이나 파티션은 변경하지 않았다.
- COM22의 ESP32-P4 v1.3에 `esptool --chip esp32p4 --port COM22 --baud 460800 --before default_reset --after hard_reset write_flash @flash_args`로 기록했다. 종료 코드 0. 부트로더·앱·파티션 테이블의 데이터 해시 검증을 모두 통과하고 재시작했다. NVS 전체 삭제는 수행하지 않았다.
- 업로드 후 12초간 시리얼 로그에서 카메라 프레임 메시지 3개를 확인했다. 해당 구간에 패닉·워치독·화면/카메라 시작 실패 문구는 없었다. 이 구간에서 서버 ping 성공은 관측하지 못했으며 서버 연결 성공으로 판정하지 않는다.
- 실제 LCD 모양과 터치, QR 출입·릴레이 동작은 사용자의 기기에서 별도 확인이 필요하다. 앞서 제공한 브라우저 시안 이미지는 실기기 화면이 아니다.
