# 출입 단말 디자인 검토

기준: Guition JC1060P470, 7인치 1024×600, ESP32-P4, LVGL.
현재 `ui.c`의 대기·QR 인식·이용안내·출입 결과와 `ui_settings.c`의 PIN 진입 화면을 대상으로 한다. 이 문서와 시안은 제안이며 펌웨어를 변경하지 않는다.

## A · 캠퍼스 라이트

- 색상: 배경 #F6F9FB, 글자 #18354B, 강조 #087B80, 보조 면 #E2F1F1, 승인 #08764D, 거부 #B73734.
- 글자: 한글 고딕. 시간은 Bahnschrift. 화면 제목 44~48px, 주요 조작 25px, 안내 23px. 실제 적용 시 기존 한글 폰트의 글리프 및 크기를 검토한다.
- 대기: `[ 시간 / 출입 안내 | 큰 QR 출입 버튼 ]`, 왼쪽 정렬.
- 인식: `[ 안내 / 이용 순서 | 320px 카메라 ]`.
- 원칙: 처음 사용하는 학생이 큰 버튼 한 개로 출입을 시작할 수 있게 한다. 시간과 출입 버튼을 분리한다.

## B · 나이트 스캐너

- 색상: 배경 #15263E, 글자 #F1F5FB, 강조 #8BC7FF, 보조 면 #243F60, 승인 #94E0BA, 거부 #FFB9AB.
- 글자: 한글 고딕, 시간 Bahnschrift. 대기 제목 54px, 인식 제목 42px, 안내 24px.
- 대기: `[ 출입 안내 / 작은 시간 | QR 출입 버튼 ]`.
- 인식: `[ 350px 카메라 | 안내 / 이용 순서 ]`, 왼쪽 정렬. 결과는 중앙 정렬.
- 원칙: 사용자의 시선이 인식 프레임에 집중되게 한다. 네이비 면과 연한 청색 프레임을 사용하며 상시 움직이는 효과는 쓰지 않는다.

## C · 블루 웨이파인딩

- 색상: 배경 #FFFFFF, 글자 #142979, 강조 #2447DB, 보조 면 #EDF1FF, 승인 #08764D, 거부 #B73734.
- 글자: 한글 고딕, 시간 Bahnschrift. 대기 제목 59px, 인식 제목 48px, 주요 조작 25px.
- 대기: `[ 파란 상단 바 ] / [ 큰 출입 안내 | 시간 ] / [ 넓은 QR 출입 버튼 ]`.
- 인식: `[ 큰 안내 | 파란 면 안의 312px 카메라 ]`.
- 원칙: 복도에서 단말의 목적을 빠르게 알아볼 수 있게 한다. 굵은 제목과 넓은 조작 영역을 중심에 둔다.

## 설계 검토 및 구현 시 유의점

세 안 모두 기존 기능과 같은 출입 흐름을 유지한다. 시간보다 출입 동작을 강조하며 관리자 설정의 시각적 비중을 줄인다. 카드와 통계가 반복되는 일반적인 대시보드 대신, 출입 안내와 인식 영역을 각 안의 중심 요소로 정했다.

- 모든 주요 터치 영역은 실제 화면 기준 52px 이상. 구현 시에도 터치 영역을 유지한다.
- 승인·거부·연결 오류를 문구와 서로 다른 기호로 구분한다. 색상만으로 결과를 전달하지 않는다.
- 결과 화면은 문 센서 확인을 뜻하지 않는다. 현재 동작에 맞춰 “문이 열립니다”로 안내한다.
- 서버 연결 실패 시 문을 열지 않는 기존 동작을 유지한다.
- 현재 서버 응답과 무관한 이름·예약·이용 인원 등은 만들지 않는다. 실습실 이름을 추가하려면 별도 데이터 연동이 필요하다.
- 미리보기는 카메라 영상 대신 안내 그림을 사용한다. 이용안내 QR도 실제 코드를 표시하지 않는다.
- 프로토타입의 PIN은 숫자 입력 모양만 검토한다. 인증·설정 저장 기능은 없다.
- 카메라 크기는 시안별로 다르다. 펌웨어 반영 시 기존 UI_PREVIEW_W/H와 실제 영상 비율을 확인하고 자르기 또는 여백 처리를 정한다.
- 실제 LVGL에서는 사각형·선·원·텍스트·카메라 영상으로 구현할 수 있다. 웹 폰트와 브라우저 렌더링의 모양이 기기에서 완전히 같다고 보장하지 않는다.

추천: A는 밝은 복도에서 익숙하고 차분한 인상을 주는 기본안. C는 먼 거리 가독성과 안내 우선 배치를 중시할 때 선택. B는 어두운 설치 환경과 스캔 화면의 집중감을 선호할 때 선택.
