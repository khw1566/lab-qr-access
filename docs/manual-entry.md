# 숫자 코드로 출입

휴대폰 출입증 화면에 표시되는 숫자 8자리를 단말의 **코드 입력**에서 입력합니다. 앞자리 `0`도 입력합니다. 지움으로 한 자리씩 수정하고 확인으로 전송합니다. 오류가 나면 화면에서 안내를 보고 다시 입력할 수 있습니다. 입력 화면에서는 카메라의 QR 인식을 잠시 멈춥니다.

숫자 코드는 해당 QR의 별칭입니다. QR과 유효기간 및 1회 사용 기록을 공유합니다. 한 방법으로 출입하면 다른 방법으로 같은 출입증을 다시 사용할 수 없습니다. 실습실, 승인 상태, 계정 정지, 긴급 잠금 등 기존 출입 규칙을 그대로 검사합니다. 휴대폰이 새 QR을 받으면 새 숫자 코드도 표시됩니다. 일반 출입증, 특별 출입증, 화면용 마스터에 적용하며 인쇄용 고정 마스터에는 표시하지 않습니다.

## 서버 연동

QR 발급 응답의 `manual_code`는 숫자 8자리 **문자열**입니다. 기존 QR 응답 필드는 유지됩니다. 단말 인증을 사용하는 `POST /api/device/verify`에 `{"code":"06271808"}`을 전송합니다. 기존 `{"token":"LA1.…"}` 요청도 유지됩니다. 한 요청에 두 필드를 함께 보내면 거부합니다.

인증된 단말마다 분 단위로 실패 횟수를 제한합니다. 같은 분에 실패가 10회 쌓이면 이후 코드 요청은 `manual_rate_limited`로 거부하며 다음 분에 초기화합니다. QR 검증은 이 제한의 영향을 받지 않습니다. 코드가 잘못되었거나 만료되면 `manual_invalid`를 반환합니다. 유효한 코드라도 기존 출입 규칙에 따라 거부될 수 있습니다.

숫자 코드 자체는 DB에 해시로 저장합니다. 별칭을 원래 서명된 QR로 변환하기 위한 QR 토큰은 만료 시각과 함께 저장하며, 새 코드 발급 시 만료된 행을 정리합니다. 발급 코드 충돌과 동시 발급을 처리합니다.

## 적용 순서와 검증

운영 변경 승인을 받은 뒤 `0008_manual_codes.sql`까지 D1 마이그레이션을 적용하고 서버·웹을 배포합니다. 이후 COM22에 새 펌웨어를 업로드합니다. 기존 서버에는 숫자 입력 기능이 없으므로 서버 갱신을 먼저 진행합니다. 현재 작업 폴더에 있는 다른 관리자 기능 변경의 배포 범위도 함께 확인해야 합니다.

로컬 검증: 서버 테스트 29개 통과, ESP32-P4 펌웨어 빌드 성공, 아이콘 112개와 고정 문구 16개의 크기·글자 검증 통과. 실제 단말의 키패드 터치와 문 개방은 업로드 후 확인합니다.
